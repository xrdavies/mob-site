BEFORE YOU BEGIN

准备工作。

  • 一台 Apple Silicon 办公室 Mac，运行 macOS 13 或更新版本，保持开机、联网、用户已登录。
  • 已安装并登录 Codex CLI 或 Claude Code（至少一个）。
  • 客户端设备能访问办公室 Mac：同一内网、公司 VPN，或按下文配置 Tailscale Serve / Funnel。
01 / INSTALL

在办公室 Mac 上安装 mobd。

打开“终端”，以普通用户身份运行（不要加 sudo）：

{{install}}

安装器会读取最新的稳定版本，校验 SHA-256 与 Apple 开发者签名，然后只把 mobd 安装到 ~/.local/bin。无需 Go、Node.js、Python 或源码。

把安装目录加入 PATH，并确认安装成功：

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
export PATH="$HOME/.local/bin:$PATH"
mobd --version
安装指定版本或自定义目录 
curl -fsSLO {{base}}/mobd/install.sh
sh install.sh --version X.Y.Z
sh install.sh --install-dir /absolute/path

可以先阅读下载的脚本再执行。历史版本见更新日志。

不使用安装脚本，手动安装

从下载页获取压缩包，对照 SHA256SUMS 校验后解压：

shasum -a 256 mobd_X.Y.Z_darwin_arm64.tar.gz
tar -xzf mobd_X.Y.Z_darwin_arm64.tar.gz mobd
mkdir -p ~/.local/bin && install -m 755 mobd ~/.local/bin/mobd
codesign --verify --strict --verbose=2 ~/.local/bin/mobd
02 / CONFIGURE

创建并编辑配置。

mobd init      # 创建 ~/.mobd/config.json，已有配置不会被覆盖
open -e ~/.mobd/config.json

mobd init 默认监听 0.0.0.0:8080，局域网和 VPN 中的设备可以直接连接；只通过 Tailscale Serve / Funnel 访问时改为 127.0.0.1:8080。用 command -v codex 或 command -v claude 查找 Agent 的绝对路径。

{
  "listen": "0.0.0.0:8080",
  "workdir": "/Users/you/Projects",
  "codexBin": "/absolute/path/to/codex",
  "runners": ["codex"],
  "defaultRunner": "codex",
  "codexPermissions": "approve"
}
{
  "listen": "0.0.0.0:8080",
  "workdir": "/Users/you/Projects",
  "claudeBin": "/absolute/path/to/claude",
  "runners": ["claude"],
  "defaultRunner": "claude",
  "claudePermissions": "approve"
}

"approve" 让 Agent 在执行命令或修改文件前询问你，问题会出现在客户端的审批卡片中。两个 Agent 都安装时，可以同时启用："runners": ["codex", "claude"]。

JSON 中只使用绝对路径

~ 和 $HOME 不会展开。修改配置后执行 mobd restart 生效。

只在受信任的网络中开放

0.0.0.0:8080 允许其他设备连接。请使用内网、VPN 或 Tailscale，并限制访问来源；不要设置公网端口转发。所有客户端都必须先配对才能访问，但 HTTP 地址不加密：没有 VPN 或 Tailscale 时，能监听网络的人可能取得凭据和内容。

03 / PERMISSIONS

授予系统权限。

  1. 系统设置 → 隐私与安全性 → 辅助功能：允许运行 mobd 的程序（终端或 mobd）。
  2. 系统设置 → 隐私与安全性 → 屏幕与系统录音：同样授权，按提示重新启动相关进程。
  3. 电源设置：避免无人值守时自动睡眠。专用的办公室 Mac 建议关闭自动锁屏：实时桌面在锁屏时也能查看和输入，但截图快照需要解锁、唤醒的屏幕。

实时桌面由 mobd 直接采集和编码（H.264），不需要开启“屏幕共享”，也不需要填写 macOS 登录密码。

04 / START

启动服务。

mobd start     # 后台运行，直到停止或注销
mobd status    # 显示监听地址和健康检查

# 可选：登录 macOS 时自动启动
mobd stop
mobd start --login

mobd status 中的检查项应全部通过。缺少的权限或 Agent 也会在客户端的设置页显示为提醒。日志位于 ~/.mobd/mobd.log，用 mobd logs 跟随查看。

05 / PAIR

配对 MOB，连接你的搭档。

每台客户端设备都要先配对一次。配对后凭据保存在设备的系统安全存储中，之后自动连接。

下面以内网地址为例。从家里或手机流量连接时，先完成 Tailscale 配置，再用生成的 HTTPS 地址配对。

  1. 安装客户端：macOS（把 mob.app 拖入“应用程序”）、Android（APK）；iPhone 版即将上线。
  2. 在办公室 Mac 上用客户端能访问的地址生成配对链接，替换为实际的内网、VPN 或 Tailscale 地址：
mobd link --url http://192.168.1.100:8080

终端会显示二维码和链接，10 分钟内有效，只能使用一次。使用 HTTP 地址时会提示传输未加密，仍可正常配对。

  1. 在 MOB 中进入 Settings → Machines → Add machine：手机扫描二维码，或在任意设备上粘贴完整链接。核对显示的办公室地址，点击 Pair。
  2. 点击 Test connection，确认各项检查通过。可在同一页设置该办公室的实时桌面画质：Auto（默认）、High，或适合慢速、按流量计费网络的 Low。
  3. 新建对话，先试一个简单任务：“查看当前屏幕，并告诉我你看到了什么。”

实时桌面默认只查看。需要自己操作时，展开大画面并切换到 Control（桌面端也可按 ⇧⌘C）。手机上点按即点击、长按为右键、双指滚动、捏合缩放。画面下方显示分辨率、帧率、流量和连接方式（如 WebRTC · LAN）；静止的桌面几乎不占流量，帧率低是正常的。

用 mobd clients list 查看已配对的设备；设备丢失时执行 mobd clients revoke CLIENT_ID，它会立即断开，其他设备不受影响。

AWAY FROM THE OFFICE

用 Tailscale，从外面连接办公室。

Tailscale 为办公室的 mobd 提供一个 HTTPS 入口。先选连接方式，再完成本节准备，最后只执行所选方式的步骤。两种方式都不需要办公室公网 IP 或路由器端口映射。

方式在哪里安装 Tailscale谁能访问入口
Serve · 优先选择办公室 Mac 和每台客户端设备同一私有网络中获准的设备
Funnel · 客户端免 VPN只需办公室 Mac公网可达，业务访问仍需 MOB 配对

tailnet 就是你的 Tailscale 私有网络。两端都能安装时选 Serve；手机不方便安装或连接 VPN 时选 Funnel。同一内网或已有公司 VPN 能直连的用户，可以继续使用内网配对。

1. 在办公室安装并登录 Tailscale

本指南办公室端统一使用 Homebrew 的开源命令行版，适用于下面两种方式。先安装 Homebrew，然后在办公室 Mac 的终端运行：

已有 Tailscale 时先确认安装方式

不要同时启动 App Store、独立 App 和 Homebrew 多套 Tailscale。已经使用 App 的 Serve 用户可以保留现有安装，按下面的说明使用对应 CLI；需要迁移安装方式时，先处理旧安装再继续。

brew install --formula tailscale
sudo brew services start tailscale
sudo tailscale up
sudo tailscale status

打开 up 输出的登录链接，登录自己的 Tailscale 账号；在 设备管理页确认办公室 Mac 在线。使用公司网络时，按管理员要求加入对应 tailnet。安装命令依据 Tailscale 官方 macOS 指引。

办公室已经安装 Tailscale App，如何使用 Serve？

打开 App，完成登录并保持连接；无需再安装 Homebrew 版。在当前终端设置下面的别名，并把后文所有 sudo tailscale 换成 tailscale。新开终端需重新设置别名，或按官方 CLI 指引配置命令行集成。下文 Funnel 步骤以 Homebrew 版为准。

alias tailscale='/Applications/Tailscale.app/Contents/MacOS/Tailscale'
tailscale status

2. 确认 mobd 在办公室本机可用

先完成前面的安装、Agent 和系统权限设置。编辑 ~/.mobd/config.json，仅把 listen 改为 127.0.0.1:8080，保留其他配置。当前任务结束后运行：

mobd restart
mobd status
curl -i --connect-timeout 5 --max-time 10 http://127.0.0.1:8080/health

未启动过服务时用 mobd start。status 应显示监听 127.0.0.1:8080；未带配对凭据的 /health 应返回 401，表示已到达认证接口，不代表 Agent 和桌面权限全部正常。本机不通时先用 mobd logs 排查。

如果地址没有变化，检查 MOBD_LISTEN 和原启动参数的覆盖。可明确运行 mobd restart --listen 127.0.0.1:8080；使用自定义配置时同时保留 --config PATH。改为本机监听后，原来的局域网直连地址将不可用。

3. 检查现有发布配置

sudo tailscale serve status
sudo tailscale funnel status

确认 Tailscale 的 HTTPS 443 根路径没有其他服务再继续；已有服务时不要覆盖。同一端口不能同时保持私有 Serve 和公网 Funnel，后执行的配置会改变可见范围。切换前先按关闭步骤停用本指南创建的旧入口。

PRIVATE / SERVE

Serve：只让自己的设备连接。

先完成办公室准备。在家里的电脑或手机上安装 Tailscale，按系统提示允许 VPN 连接，登录与办公室相同的 tailnet，并在使用 MOB 时保持连接。

1. 限制访问范围

在 Tailscale 访问控制中，只允许需要使用 MOB 的设备访问办公室 Mac 的 TCP 443，不需要另开放 8080。实时桌面的 WebRTC 画面在 tailnet 内直接连到 mobd 的 UDP 端口；只放行 TCP 443 时，画面自动改用经过这个入口的 WebSocket 方式。

专用两台设备的访问规则示例

从设备管理页读取真实 Tailscale IP；办公室也可运行 sudo tailscale ip -4。将下面 src 换为客户端 IP、dst 换为办公室 IP。这个完整示例只适用于专门为这两台设备建立的 tailnet：

{
  "grants": [
    {
      "src": ["100.101.102.103"],
      "dst": ["100.101.102.104"],
      "ip": ["tcp:443"]
    }
  ]
}

放行规则会累加：仅添加这条规则不会收紧已有的全放行规则。专用网络需移除宽泛放行；共享或公司网络请管理员调整相关规则，保留其他业务配置，不要直接覆盖整份策略。设备 IP 变化后同步更新。参见官方 grants 语法。

2. 在办公室启用私有 HTTPS

sudo tailscale serve --bg --https=443 http://127.0.0.1:8080
sudo tailscale serve status
sudo tailscale funnel status

首次运行按终端链接启用 HTTPS 证书，并确认 tailnet 已开启 MagicDNS；没有权限时联系管理员。成功后应看到 Available within your tailnet，且 Funnel 状态没有将这个端口公开。复制输出中的完整 HTTPS 地址，继续远程配对与验收。

Serve 的入口只对获准的私有网络设备开放，但仍需 MOB 配对。参考 Serve 官方说明。

PUBLIC / FUNNEL

Funnel：手机不装 Tailscale 也能连接。

先完成办公室准备，客户端只需安装 MOB 和正常联网。此方式由 Tailscale 提供公网 HTTPS 转发，不需要自备服务器。

这是公网入口

任何人都可能访问这个域名，业务访问由 mobd 配对认证保护，不能依靠私有网络访问规则筛选公网访客。只给可信设备发送邀请，保持 mobd 更新；不要把 mobd 的 8080 直接映射到公网。

Funnel 需要 MagicDNS、HTTPS 证书和账号的 Funnel 权限。首次执行后按终端链接启用；权限不足请 tailnet 管理员处理。下面命令使用前文的 Homebrew 版：

sudo tailscale funnel --bg --https=443 http://127.0.0.1:8080
sudo tailscale funnel status

成功后应看到 Available on the internet 和实际的 HTTPS 地址。复制这个地址，继续远程配对与验收。公网 DNS 首次生效可能需要几分钟。

Funnel 只转发 TCP：实时桌面会在约 5 秒后自动改用较慢的 WebSocket 方式（之后连接同一办公室时约 1 秒），画质和延迟不如 Serve / 内网。Funnel 还有带宽限制，请用手机流量实测桌面延迟；套餐和办公用途以 Tailscale 当前条款为准。要求及限制见 Funnel 官方说明。

CONNECT / VERIFY

用 HTTPS 地址配对，再测试实际连接。

Serve 和 Funnel 使用相同的 MOB 配对流程。下文的 office-mac.your-tailnet.ts.net 是示例，务必换成终端实际输出的域名；保留 https://，不要追加 :8080 或其他路径。

1. 从客户端所在网络检查入口

Serve 用户保持客户端 Tailscale 在线；Funnel 用户用手机关闭 Wi-Fi、断开 Tailscale，以蜂窝网络测试。在浏览器打开实际域名的 /pair 页面，应看到 mobd 配对提示；仅打开此页不会完成配对。也可在客户端电脑运行：

curl -i --connect-timeout 10 --max-time 15 https://office-mac.your-tailnet.ts.net/health

预期返回 mobd 的 401，说明网络和认证入口可达。超时、502 或证书错误时先看排错说明，不要跳过证书验证。

2. 在办公室生成邀请，在客户端完成配对

mobd link --url https://office-mac.your-tailnet.ts.net
  1. 打开 MOB 的 Settings → Machines → Add machine，扫描二维码或粘贴完整邀请链接，核对 HTTPS 地址后点击 Pair。每台设备单独生成邀请，邀请 10 分钟内有效且只能使用一次。
  2. 运行 Test connection。打开实时桌面后，画面下方应显示 WebRTC · Tailscale（Serve）或 WebSocket（Funnel）。
  3. 发起“查看当前屏幕，并告诉我你看到了什么”，确认任务进度实时更新、截图和桌面能打开；再测试上传图片、打开附件以及断线后重新连接。

Serve 用户还应确认：客户端断开 Tailscale 后，新请求不再到达；未获准的 tailnet 设备也无法访问。所有配对设备共享同一办公室的会话和桌面，配对不提供用户间的数据隔离。

3. 保持办公室可用

--bg 保存 Serve / Funnel 的后台配置，Tailscale 重启后会恢复；它不会替你启动 mobd。需要登录 macOS 后自动启动 mobd 时，已运行的服务执行 mobd restart --login，未运行时执行 mobd start --login。

办公室 Mac 仍需保持唤醒、联网和用户登录，Tailscale 也必须在线。日常重启不需要重新配对；设备名、tailnet 名或注册身份变化可能改变入口，届时需核对客户端地址。

TROUBLESHOOT / DISCONNECT

连接不通时，逐段检查。

现象检查方法
办公室本机也不通先看 mobd status 和 mobd logs，确认监听端口及服务状态。
Serve 超时或域名无法解析确认两端在同一 tailnet 且在线，检查 MagicDNS、客户端使用 Tailscale DNS，以及访问策略是否放行办公室 TCP 443。用 sudo tailscale status 和 sudo tailscale netcheck 检查办公室网络。
Funnel 在手机流量下不通检查 sudo tailscale funnel status 是否显示公网入口、HTTPS / Funnel 权限及办公室在线状态；首次发布等待 DNS 生效。
入口返回 502在办公室重试本机 /health；确认 mobd 正在运行，转发目标为实际的 HTTP 监听端口。
证书错误使用终端输出的完整 HTTPS 域名，检查 DNS、系统时间和证书启用状态，不要改用 IP 或关闭证书验证。
配对后客户端仍报 401裸 curl 的 401 是预期；MOB 内的 401 则需检查设备是否被撤销，使用新邀请重新配对。
聊天正常，桌面打不开或很慢先看客户端显示的原因（屏幕锁定或休眠、缺少屏幕录制权限、“Update mobd”需升级办公室 mobd）；画面慢时看读数中的连接方式和信号格，用 sudo tailscale status 查看是否经过 relay 中继，并检查办公室上行带宽。Funnel 走 WebSocket，还有带宽限制。

关闭入口或切换方式

在办公室只运行与你所选方式对应的一组命令；以下仅关闭本指南在 443 上建立的入口，保留其他端口配置。

关闭 Serve：

sudo tailscale serve --bg --https=443 off
sudo tailscale serve status

关闭 Funnel：

sudo tailscale funnel --bg --https=443 off
sudo tailscale funnel status

不要用 serve reset 或 funnel reset 清除同机其他服务。关闭入口不会撤销 MOB 已配对凭据；只需移除某台设备时，在办公室运行 mobd clients list，再用 mobd clients revoke CLIENT_ID 撤销它。

网络命令与关闭方式可对照官方 Serve CLI 和 Funnel CLI。需要使用自己的公网服务器和域名时，参考进阶的 Caddy + Tailscale 网关手册。

KEEP MOB CURRENT

更新与卸载。

更新 mobd：等当前任务结束，然后：

mobd stop
{{install}}
mobd start            # 或 mobd start --login 恢复登录启动

配置、会话和附件都会保留。

更新客户端：macOS 版启动时自动检查更新，也可在 Settings → About 中手动检查。Android 版下载新 APK 覆盖安装。

卸载 mobd：执行 mobd stop，删除 ~/.local/bin/mobd。配置位于 ~/.mobd，会话数据位于 ~/Library/Application Support/mob，按需备份或删除。

A FEW GOOD QUESTIONS

常见问题。

为什么连接不上办公室 Mac？

内网直连需确认 mobd 的监听地址、防火墙和两端网络互通。Tailscale 连接请按排错说明检查 Serve / Funnel 入口，再在客户端使用 Test connection 查看具体项目。

客户端提示需要重新配对？

这台设备的凭据已被撤销，或办公室执行了认证重置。在办公室 Mac 上重新运行 mobd link --url …，在客户端对该办公室选择 Pair again 并扫描或粘贴新链接，对话会保留。配对链接过期或已被使用时，同样重新生成即可。

为什么只能聊天，看不到桌面？

客户端会显示原因：缺少屏幕录制权限时，在办公室 Mac 授予后重启 mobd；提示“Update mobd”时更新办公室的 mobd；截图提示屏幕锁定时，解锁或关闭自动锁屏（实时桌面在锁屏时仍可打开）。不再需要“屏幕共享”或 macOS 登录密码。

实时桌面用什么方式传输？流量大吗？

在内网和 Tailscale 下用 WebRTC，H.264 画面按客户端窗口大小编码，并随网络自动调节码率、分辨率和帧率；画面不变时几乎不发送数据。只通 TCP 的入口（Funnel、HTTPS 网关）自动改用 WebSocket。可按办公室选择 Auto / High / Low 画质。

安装器提示 mobd 正在运行？

先结束任务并执行 mobd stop（前台运行的 mobd serve 需手动停止），再重新运行安装命令。

我的内容会发送到哪里？

桌面运行在办公室 Mac，客户端直接连接 mobd。任务内容、截图等是否发送给模型服务取决于你使用的 Agent 和模型配置，请查看对应服务的数据政策。

支持 iPhone、Intel Mac 或 Windows 吗？

iPhone 与 iPad 版即将上线；Android 版已可下载。MOB 桌面端和 mobd 目前只支持 macOS Apple Silicon。
